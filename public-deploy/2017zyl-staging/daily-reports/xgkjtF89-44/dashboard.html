01 / BRIEF

核心
判断Signal
brief

这不是“如何多跑几个 agent”的教程；它是在追问：当实现速度暴涨后，人类应该守住哪些前置判断。This is not a tutorial about running more agents. It asks which upstream judgments humans must retain when implementation speed explodes.

EDITORIAL SYNTHESIS
不要把人从环里拿掉。把人移到设计、验证与瓶颈判断的位置。Do not remove humans from the loop. Move them to design, verification, and bottleneck judgment.
视频最强主线：实现已经加速，审查、信任、系统掌控与长期可改性开始决定产出上限。The strongest through-line: implementation is faster; review, trust, system command, and long-horizon changeability now cap throughput.

编码从小时/天缩短到分钟/小时，审查与信任接棒成为约束。Coding drops from hours or days to minutes or hours; review and trust inherit the constraint.

48:50先找约束Find the constraint

02 / GATES

四道
设计门Four
design gates

先让低置信、难逆转的决策暴露，再让 agent 写代码。四层都不是文档仪式，而是缩小错误搜索空间。Expose low-confidence, hard-to-reverse decisions before coding. Each layer narrows the costly part of the search space.

产品结果Product outcome

明确用户问题、可度量成功、面向用户的发布说明；用纯 HTML mockup 先把界面说清。Define the user problem, measurable success, and launch story; clarify the interface with a plain HTML mockup.

  • 用户能完成什么？What can the user now do?
  • 什么数字会变化？Which number should move?
11:50–15:15

系统架构System architecture

服务流、端点、表、查询与边界如何拼接；把外部系统的必要说明留在 repo 内。Map services, endpoints, tables, queries, and boundaries; keep essential external-system context in the repository.

  • 数据从哪来、到哪去？Where does data enter and leave?
  • 哪条边界最难逆转？Which boundary is hardest to reverse?
15:16–16:36

程序设计Program design

调用栈、文件位置、类型/方法签名与测试形态。编码前先审低置信决策。Specify call stacks, file placement, signatures, and test shape. Review low-confidence decisions before code.

  • 哪些选择会让后续功能更难？Which choice makes later features harder?
  • 人类直觉应在哪里介入？Where should human intuition enter?
16:37–19:28

纵向切片Vertical slices

先用 mock API + stub UI 打通最小端到端，再逐层增加迁移、逻辑和错误处理；每步可验证。Connect a minimal end-to-end path with mock API and stub UI, then add migrations, logic, and errors—each verifiable.

  • 每片都能独立演示吗？Can each slice be demonstrated?
  • 失败已变成回归测试吗？Did failure become a regression test?

反证 01：通过测试 ≠ 可维护Counterproof 01: tests ≠ maintainability
