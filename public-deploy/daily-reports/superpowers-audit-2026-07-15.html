2 · The real increment is the workflow chain, not individual skills

Patrick's 165+ skills are a parts library. obra/superpowers is the assembly manual. The 14 skills chain into:

// obra's intended workflow chain
brainstorming  →  writing-plans  →  subagent-driven-development
                                       ↓ (per task)
                              requesting-code-review
                                       ↓ (final)
                              receiving-code-review  →  finishing-a-development-branch  →  verification-before-completion

Patrick currently has the blocks but not the sequencing. The 4 strong-gap skills above are the missing link-ends of this chain. Picking just brainstorming + finishing-a-development-branch would already close 2 of the 3 chain breaks.

Chain read: Patrick's last 5 sessions (e.g. 2026-07-12 daily-reports v8 polish) involved ~6 hours of building, but the entry (brainstorm) and exit (finishing branch + verification gate) of those sessions were often skipped or compressed into memory rather than a real workflow. obra's chain would make those steps visible and auditable.

3 · The 4 strong-gap skills, deep-dive

GAP #1

brainstorming

Patrick has grilling (single-question interview), align (clarify rounds), domain-modeling (bounded-context) — but no "no implementation until design approved" workflow. Sessions often jump from "make a v8 daily-reports" directly to write_file of new HTML.

"Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until you have presented a design and the user has approved it. This applies to EVERY project regardless of perceived simplicity."
— obra/superpowers brainstorming/SKILL.md
obra's answer: HARD-GATE HTML directive. "Every project goes through this process. A todo list, a single-function utility, a config change — all of them. 'Simple' projects are where unexamined assumptions cause the most wasted work."
📦 10KB SKILL + 13KB visual-companion⏱ reverse-port 1h🎯 HIGH
GAP #2

finishing-a-development-branch

Patrick has no formal PR / merge / cleanup workflow. gh-pr-workflow exists in github/ as low-level primitives, but no "tests pass → detect env → present options (merge / PR / cleanup) → execute → cleanup worktree" workflow.

"Verify tests → Detect environment → Present options → Execute choice → Clean up."
— obra/superpowers finishing-a-development-branch/SKILL.md
obra's answer: 5-step recipe: run test suite first, then detect (GitHub repo? bare git? plain files?), then 4-option menu (merge / PR / cleanup / leave), then execute, then nuke worktree.
📦 6.8KB SKILL⏱ reverse-port 0.5h🎯 MEDIUM-HIGH
GAP #3

receiving-code-review

Patrick has requesting-code-review but not how to receive code review. code-review/ contains only zoom-out-explainer — no skill for "subagent sends back 'fix X, Y, Z' — how to evaluate technically without performing agreement".

"Code review requires technical evaluation, not emotional performance. Verify before implementing. Ask before assuming. Technical correctness over social comfort."
— obra/superpowers receiving-code-review/SKILL.md
obra's answer: 6-step pattern: READ → UNDERSTAND (restate in own words) → VERIFY (against codebase reality) → EVALUATE (sound for THIS codebase?) → RESPOND (technical ack or reasoned pushback) → IMPLEMENT (one item at a time, test each).
📦 6.4KB SKILL⏱ reverse-port 0.5h🎯 MEDIUM
GAP #4

verification-before-completion

Patrick has agent-self-evaluation (5-axis scorecard at task end), agent-trace-integrity (no fabrication), audit (cron / site health) — all post-hoc. None are a pre-claim hard gate that says "evidence before assertions always".

"NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE. If you haven't run the verification command in this message, you cannot claim it passes."
— obra/superpowers verification-before-completion/SKILL.md
obra's answer: 4.2KB tight gate function. Iron Law = "no completion without fresh verification". Forces "I ran X, output Y" before "fixed". Composes well with Patrick's existing agent-self-evaluation.
📦 4.2KB SKILL⏱ reverse-port 0.5h🎯 HIGH

5 · Risk assessment

⚠ Hazard C — blanket install overwrites local patches. Patrick's meta/claude-superpowers/SKILL.md (already in the library) has Hazard C documented: npx skills add ... -g replaces skill directories silently. Never blanket-install. Always cherry-pick + reverse-port to Patrick's SKILL.md schema (gene / capsule / depends_on).
⚠ Frontmatter schema drift. obra uses standard frontmatter (name, description). Patrick extends with gene + capsule + depends_on. Direct install would lose these fields and break Patrick's skill routing. Reverse-port is mandatory.
⚠ Vendor lock by another name. obra/superpowers is MIT and supports 10 coding agents (Claude Code, Codex, Cursor, Pi, OpenCode, etc.) — not strict vendor lock. But design assumptions (e.g. <HARD-GATE>, <SUBAGENT-STOP>, subagent protocols) are Claude Code idioms. Pi is officially supported but secondary. Mitigation: test on a small pilot (one skill, one task) before committing all 4.
