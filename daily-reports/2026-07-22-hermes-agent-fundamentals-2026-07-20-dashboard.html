核心论点Core theses

01 · FOUNDATION

先选择运行位置，再选择模型Choose where the agent lives before choosing the model

专用本地机、VPS、旧电脑或 Docker 隔离的个人电脑各有取舍。长期可用性、在线时间和隔离边界，比盲目追求最大模型更重要。A dedicated local machine, VPS, old computer, or a Docker-isolated personal computer each has trade-offs. Availability and isolation matter before chasing the largest model.

02 · CAPABILITY

Provider 是入口，Tools 才是行动能力Providers are the entry point; tools create agency

模型负责理解与规划，工具负责搜索、浏览、文件操作和消息发送。没有工具，Agent 只能回答，无法完成闭环任务。Models understand and plan; tools search, browse, edit files, and send messages. Without tools, an agent can answer but cannot close the loop.

03 · REUSE

Skill 把一次性 Prompt 变成可积累能力Skills turn one-off prompts into reusable capability

把提示词、评价维度、输出格式和判断流程封装起来，下次遇到同类问题即可复用、组合和迭代。Package prompts, criteria, output formats, and decision flows so similar work can be reused, composed, and improved.

04 · AUTOMATION

Cron 让 Agent 从被动问答变成主动系统Cron turns a reactive agent into a proactive system

每日研究、定期检查和周期性汇总都适合做成受控的定时任务。关键是定义触发频率、输出位置和失败策略。Daily research, checks, and recurring summaries fit scheduled jobs. Define cadence, output location, and failure behavior.

05 · MEMORY

记忆是分层系统，不是一个无限膨胀的文件Memory is layered, not one infinitely growing file

核心记忆保存稳定事实，会话检索找回历史上下文，外部记忆捕捉隐含模式，Obsidian 承担可读、可链接的长期知识。Core memory stores stable facts; session search recovers context; external memory captures patterns; Obsidian holds readable, linkable knowledge.

06 · SECOND BRAIN

Obsidian 是可检查的第二大脑Obsidian is an inspectable second brain

把对话产生的计划、项目上下文和每日记录写入 vault，让成果跨会话保存，并且由人直接检查和链接。Write plans, project context, and daily records into a vault so results persist across sessions and remain inspectable.

07 · LOCAL AI

本地模型的优势是成本与隐私Local models optimize cost and privacy

Ollama 和 llama.cpp 让本地推理更容易。实用的路径不是云端/本地二选一，而是按任务风险和推理要求做路由。Ollama and llama.cpp simplify local inference. The practical choice is routing by task risk and reasoning needs, not cloud versus local.

08 · ORCHESTRATION

多 Agent 的收益来自清晰分工Multi-agent value comes from clear division of labor

并行起草规格、修改样式、提出想法，再用 Kanban 协调任务。数量本身不是关键，共享产物和可验证交付才是。Draft specs, change styles, and generate ideas in parallel, then coordinate with a Kanban. Shared artifacts and verifiable delivery matter more than agent count.

系统分层：从对话到 Agent 基础设施System layers: from chat to agent infrastructure

核心框架：Model/Provider → Tools → Skills → Cron → Memory → Obsidian → Multi-agent orchestration。Core framework: Model/Provider → Tools → Skills → Cron → Memory → Obsidian → Multi-agent orchestration.

每增加一层，系统就从“能回答”向“能执行、能复用、能自动运行、能积累、能协作”推进。不要一开始就堆满所有组件，先让一个小闭环可靠运行，再扩展下一层。Each layer moves the system from answering toward executing, reusing, automating, accumulating, and collaborating. Start with one reliable loop, then add layers.

实施清单Implementation checklist

  • 选择运行位置，并明确在线性、隔离性与维护成本。Choose a runtime and clarify availability, isolation, and maintenance cost.
  • 连接主模型提供商，为高频低风险任务准备本地模型。Connect a primary provider and prepare a local model for frequent low-risk tasks.
  • 先熟悉 Tools，再把重复流程写成 Skill。Learn the tools first, then turn repeated workflows into Skills.
  • 为每日/每周工作设计 cron，并写清失败时该做什么。Design cron jobs for recurring work and define failure behavior.
  • 保持核心记忆精简，把研究与项目上下文放进 Obsidian。Keep core memory lean; put research and project context in Obsidian.
  • 从一个小 companion app 或研究工作流开始试验多 Agent 并行。Start multi-agent parallelism with one small companion app or research workflow.
  • 为自动化任务加验证步骤，不把“运行了”误认为“完成了”。Add verification to automations; do not confuse “ran” with “finished.”
