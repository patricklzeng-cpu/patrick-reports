从零到 App Store / Play Store

STEP 1

先做真实设备上的最小闭环

不是先设计完整产品，而是让 Expo 项目通过 QR code 在手机上运行，缩短反馈回路。

STEP 2

React Native + Expo

React Native 提供跨平台组件模型，Expo 管理开发体验、设备预览和云构建。

STEP 3

Claude Code 负责脚手架与迭代

通过自然语言生成、审阅、修复 TypeScript，再持续在真机上验证。

STEP 4

上架不是一个按钮

证书、bundle id、隐私声明、商店账号、截图、审核和支付都需要单独处理。

环境搭建

01 · Claude Code

安装 CLI、登录并为项目创建独立目录。不要把密钥写进客户端代码。

02 · Expo toolchain

创建 Expo/React Native TypeScript 项目，启动 dev server。

03 · Expo Go

手机安装 Expo Go，扫描终端 QR code，在真实设备上打开项目。

04 · Store accounts

Apple Developer 和 Google Play Console 是发布所需的外部账号与费用。

Prompt → Code → Typecheck → Device 的闭环

01

定义 1 个用户任务

先描述一个可在 5 分钟内验证的行为。

02

让 Agent 解释计划

要求列出文件、依赖和风险。

03

生成最小实现

不要一次塞入认证、支付和离线同步。

04

运行 TypeScript 检查

把静态错误清零再进设备。

05

真机扫描 QR

触摸、键盘、权限和网络问题只有真机能暴露。

06

记录失败并迭代

把报错全文交给 Agent，不只说“坏了”。

真机测试

QR code 是最快反馈路径

Expo Go 扫描 EXP link，让代码在真实 iOS/Android 设备上运行。

真机优于只看模拟器

相机、通知、键盘、安全区、触摸和弱网行为需要真机验证。

开发模式 ≠ 生产包

Expo Go 可验证大部分 UI/逻辑，但原生模块和商店包仍需 EAS build。

测试矩阵

至少覆盖 1 台 iPhone + 1 台 Android、冷启动、离线、权限拒绝和升级路径。

数据、认证与安全

WARN

客户端不是秘密存储

publishable key 可公开不代表所有 key 都可公开；服务端密钥必须留在后端。

WARN

认证需要行级授权

不能只实现登录 UI；每条数据读取都要验证当前用户权限。

MITIG

先做数据模型

让 Agent 先写 schema、访问规则和迁移，再写页面。

MITIG

可观测性

记录 crash、network failure、版本号和匿名设备上下文，才能闭环修复。

可复用 Prompt 模式（意图级，不伪造视频逐字稿）

Architecture prompt

Before coding, propose a React Native + Expo architecture. List files, state boundaries, data flow, native permissions, and a smallest testable slice.

Verification prompt

Run the TypeScript checker and tests. Fix root causes, not symptoms. Then give me the exact Expo command and a 5-step true-device smoke test.

Security prompt

Classify every credential as public, client-safe, or server-only. Identify authorization rules and verify no server secret ships in the mobile bundle.

Release prompt

Prepare separate iOS and Android release checklists: identifiers, credentials, store metadata, privacy declarations, internal testing, and rollback.

90 分钟复刻清单

  1. 写 1 句用户任务与 3 条验收标准。
  2. 创建 Expo TypeScript 项目。
  3. 让 Claude Code 先解释目录与数据流。
  4. 实现 1 个 screen + 1 个本地状态。
  5. 运行 TypeScript checker，清零错误。
  6. Expo Go 扫 QR，在真机完成 5 步 smoke test。
  7. 再决定是否增加后端、认证和 EAS build。
停止线：第一个闭环没跑通前，不加支付、推送、社交登录或复杂数据库。
