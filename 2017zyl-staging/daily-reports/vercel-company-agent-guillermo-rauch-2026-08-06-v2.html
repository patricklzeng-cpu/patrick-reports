核心判断Core judgment

Agent 的护城河不在模型，在公司方法。The moat is not the model. It is the company's method.

模型会更快、更便宜，也会被替换。真正能积累的是：资深员工如何判断、哪些证据可信、什么时候需要批准、失败怎样回归测试。把这些写成 Skill，才把一次优秀表现变成组织能力。Models become faster, cheaper, and replaceable. What compounds is how experts decide, which evidence they trust, when approval is required, and how failures become regression tests. A skill turns one strong performance into organizational capability.

产品形态Product shape

一个名字，一扇门，一队专家。One name, one door, a team of experts.

员工在 Slack 中找 V；V 再调用内容、数据、知识和编码能力。统一的是体验与责任，不是底层执行器。Employees meet V in Slack; V calls content, data, knowledge, and coding capabilities. The experience and accountability are unified—not the executor underneath.

能力边界Capability boundary

Tool ≠ PermissionTool ≠ Permission

接入 WordPress 只说明“能发布”；当前用户是否能发布，是另一层产品逻辑。Connecting WordPress means publishing is possible. Whether this user may publish is a separate product decision.

设计原则Design principle

先让一次工作可信，再让它主动。Make one workflow trustworthy before making it proactive.

如果没有明确输入、证据、审批和 Eval，主动性只会放大模糊。正确顺序是：边界化 Skill → 最小工具 → 身份权限 → 可核查结果 → Trigger。Without explicit inputs, evidence, approval, and evaluations, proactivity magnifies ambiguity. The right order is bounded skill, minimal tool, identity-aware authority, verifiable output, and only then a trigger.

02PLATFORM SHIFT
访谈框架Interview framing

从“缩小界面”到“创造新用例”。From shrinking interfaces to creating new use cases.

Guillermo 用 PC 与移动革命类比 Agent：新平台的价值不是把旧界面搬过去，而是出现原来做不到的行为。Agent 的新行为，是让知识工作者调用编码能力，并让组织在无人盯屏时继续工作。Guillermo compares agents with the PC and mobile revolutions: a new platform matters when it enables behavior that was previously impossible, not when it merely ports the old interface. Agents let knowledge workers invoke coding as a capability and let organizations continue useful work without a person watching the screen.

03AGENT STACK
结构化综合Structured synthesis

六层智能栈：从灵魂到评估。A six-layer intelligence stack, from soul to evaluation.

这六层不是六个功能列表，而是一条依赖链。身份约束方法，方法选择工具，身份与任务共同收缩权限，触发器启动工作，评估把结果重新写回方法。These are not six independent features. They form a dependency chain: identity constrains method; method chooses tools; user and task scope authority; triggers start work; evaluations feed results back into the method.

权限公式Authority formula
能力 = Skill ∩ 身份 ∩ 任务 ∩ 环境 Authority = Skill ∩ Identity ∩ Task ∩ Environment

“Agent 有发布工具”不等于“当前用户能让 Agent 发布”。把交集做成产品逻辑，才能共享方法而不共享越权。An agent having a publishing tool does not mean the current user may publish through it. Productize the intersection so methods can be shared without sharing excess authority.

04PRODUCT ARCHITECTURE
Vercel V 模式Vercel V pattern

产品上是一个 Agent，系统上是一支团队。One agent in the product, a team in the system.

“God Agent 还是多 Agent”不是二选一。员工需要一个无需学习路由规则的前门；执行层需要不同上下文、工具、成本和权限的专业能力。“God agent or many agents” is a false binary. Employees need one front door that hides routing complexity. Execution needs specialists with different contexts, tools, cost profiles, and authority.

真正的工程难题The real engineering problem

交接时，身份与责任不能丢。Identity and accountability must survive every handoff.

多 Agent 的难点不是“会不会调用”，而是任务状态、身份声明、最小权限、证据链和失败恢复能否跨边界保持一致。没有这些，统一入口只是把复杂性藏起来，而不是解决它。The hard part of multi-agent systems is not whether one agent can call another. Task state, identity claims, least privilege, evidence, and recovery must remain coherent across boundaries. Otherwise the front door only hides complexity.

05PROACTIVITY LOOP
从提示到运营From prompting to operations

主动不是自由发挥，而是闭环运行。Proactivity is not free-form autonomy. It is a closed loop.

当 Agent 在夜间扫描机会、响应事件、主动总结时，价值从“回答速度”迁移到“发现本来不会被问到的问题”。但主动性必须绑定证据、复核和 Eval。When an agent scans overnight, responds to events, and summarizes without being asked, value shifts from answer speed to discovering questions no one would have remembered to ask. That proactivity must remain coupled to evidence, review, and evaluation.

06PERMISSION DESIGN
现实约束Operational constraint

共享 Skill，不共享越权。Share the skill, not the excess authority.

团队希望复用同一种高质量方法，但个人邮箱、客户数据和发布凭据不能因此扩散。权限必须跟随身份和任务，而不是永久附着在 Agent 名字上。Teams want to reuse the same high-quality method, but personal email, customer data, and publishing credentials must not spread with it. Authority should follow identity and task—not remain permanently attached to the agent's name.

10EDITORIAL VERDICT
独立判断Independent assessment

最值得带走的，不是某个 Agent 产品。The most valuable takeaway is not a specific agent product.

真正值得复制的是组织设计：把隐性方法变成 Skill，把能力与授权拆开，把统一体验建立在专业执行之上，再用 Eval 让系统持续变好。What deserves replication is the organizational design: turn tacit methods into skills, separate capability from authority, place a unified experience over specialist execution, and use evaluations to make the system improve.

这套叙事最强的三点Where the thesis is strongest

  1. Skill 是可累积的公司 IP。Skills are compounding company IP. 它把专家经验从个人记忆变成可测试资产。They turn expert memory into a testable asset.
  2. 一个入口与多 Agent 解耦。One interface is decoupled from many agents. 统一体验不必牺牲执行边界。A unified experience need not erase execution boundaries.
  3. 速度与准确成为两种模式。Speed and accuracy become separate modes. 模型路由终于服从工作，而不是品牌。Routing serves the work rather than the brand.

仍然欠账的四件事What remains unresolved

  1. 效果归因：Causal impact: 省时不等于创造价值。saving time is not the same as creating value.
  2. 组织激励：Incentives: 谁贡献方法，谁拥有与维护？who contributes, owns, and maintains the method?
  3. 监控边界：Surveillance: 连接越多，治理责任越重。more connections create more governance duty.
  4. 故障隔离：Fault isolation: 统一入口也可能成为统一故障域。one front door can become one failure domain.
