02

THE MENTAL MODEL

模型是飞行员，Harness 是整套驾驶舱。

Chatbot 的核心是“你问，它答”；Harness 的核心是让模型在一个可执行、可约束、可恢复、可复盘的循环里工作。

CHATBOT
你问它答

一次对话，输出主要是文字。

HARNESS
理解环境制定步骤调用工具验证结果

多步循环，输出可以是被验证过的真实改动。

当前节点 · 模型

负责推理与生成，例如 DeepSeek V4 Flash。它是“大脑”，不是整个 Agent。

模型负责判断下一步；Harness 负责让下一步可执行、可约束、可恢复、可复盘。

03

10-MINUTE TAKEOFF

第一次起飞：只做一件不会后悔的事。

从实验目录和只读任务开始。每一步都给你“会发生什么、成功标志、如何停下”。

  1. 01

    先准备一个可丢弃的实验目录

    不要从桌面根目录、真实密钥目录或唯一副本起步。最好使用有 Git、已备份的项目副本。

    成功标志这个目录即使被误改，也能完整恢复。
  2. 02

    检查 Node.js

    官方快捷路径只要求安装 Node.js；为了与当前源码要求一致，建议使用 Node 22.19+。

    复制到终端
    node --version
    成功标志看到 v22.19.0 或更高的兼容版本。
  3. 03

    启动 Web UI

    固定版本便于复现本指南；若想始终使用最新预览版，可删除版本号。

    复制到终端
    npx @deepseek-ai/dsh@0.1.2-rc.1 web
    成功标志浏览器打开，或终端打印 http://127.0.0.1:3080。
  4. 04

    配置模型与工作区

    依次打开 Settings → Models 填入 API Key，再用 Choose workspace 选择刚才的实验目录。

    成功标志输入框从禁用变为可发送；模型选择器显示可用模型。
  5. 05

    完成第一次只读侦察

    选择标准模式与“仅可查看”，发送下面的安全提示词。先证明它看懂了，再允许修改。

第一条提示词：先只读，再决定

请用小白能懂的话告诉我：

PRESET ≠ PROFILE

“带什么装备”和“从哪扇门进入”，是两件事。

Agent Preset 决定单个会话有哪些工具、提示与 Skills；Profile 决定整个应用如何启动。把它们分开，你就不会被名称绕晕。

记忆锚点

Preset 像 Agent 的装备包；Profile 像进入系统的舱门。

06

THE GOLDEN LOOP

最强工作流，不是最大权限；是每一步都有证据。

把这个八步环养成肌肉记忆。复杂任务只是环更长，判断标准并没有变。

01侦察只读找入口、规则、测试、风险
02计划把目标变成可验收的小步骤
03批准人确认范围与必要权限
04执行Todo 驱动最小修改
05并行只拆真正独立的子问题
06验证测试、构建、实际输出
07复盘查看轨迹、成本与失败点
08选择结束、Fork 或 Compact
BEFORE

先让它证明理解

要求先读真实代码、规则与错误，再提交可验收计划。高风险任务同时使用 Read Only。

规划模板
/plan
先只读检查真实代码，再提交一份不超过 5 步的完整计划。
包含：成功标准、涉及文件、边界情况、测试、风险与假设。
计划获批前不要修改文件。
DURING

小步改，小步验

建立 Todo；只改必要文件；读完整错误；失败时调整假设，而不是机械重试。

执行模板
按已批准计划执行。
每完成一项就更新 Todo；不顺手重构无关内容。
修改后先跑最小相关测试，再跑项目要求的完整验证。
最终列出改动、证据、遗留风险和未做事项。
AFTER

用独立验收收口

不要相信上一条“已完成”。让它重新读 diff、重跑验证，逐条核对成功标准。

独立验收模板
现在充当独立验收者，不要相信上一条完成声明。
重新读取实际 diff，运行相关测试，逐条核对成功标准。
只输出：通过项、失败项、证据、剩余风险。
发现问题先报告，不要修改。

PROMPT LAB

把“帮我做一下”，升级成可执行合同。

好提示词不靠长，而靠边界完整。选一个场景，改四个字段，右侧会即时生成可复制任务。

已生成任务合同
目标：用小白能懂的语言解释这个项目的用途、入口、主要目录和测试方式。
范围：整个工作区；只读。

先做：先检查真实现状与适用的项目规则；给出不超过 5 步的计划。未经批准，不开始高影响修改。
允许：在约定范围内读取、分析；获批后只做完成目标所需的最小操作。
禁止：不要修改文件，不要安装依赖，不要猜测没有证据的内容。
验收：每条结论引用文件路径或实际命令结果；列出 3 个仍不确定的问题。
停止条件：遇到权限扩大、数据损失风险、需求歧义或外部写入时，先停下向我说明。
完成后：列出变更、验证证据、残余风险、可回滚方式，以及唯一建议的下一步。
目标范围先做允许禁止验收停止条件回报格式

SAFETY BELT

权限不是“信不信 AI”，而是一次失误能影响多大范围。

官方明确：沙箱、审批与权限只能降低风险，不能保证隔离。真正的底线仍然是可丢弃环境、备份、最小访问和人工确认。

尚未安全审计 · 不应视为生产安全

模型错误、恶意输入、配置错误或不可信插件都可能损坏文件、泄露数据或凭据。

沙箱主要约束文件副作用

网络与进程可见性不属于这套文件沙箱词汇；Windows ACL 与旧 Landlock 还可能只有 partial enforcement。

“本地优先”不等于“完全离线”

模型 API、Web、MCP 与第三方插件可能把内容发往各自服务。先画清每一个数据出口。

密钥只写，但仍是敏感文件

模型页只返回脱敏描述；明文凭据保存在 $DSH_HOME/.credentials.yaml。不要提交、同步或截图。

反馈可能带出会话记录

当前基础配置的会话遥测由 /feedback 触发；提交前审查内容。隐私敏感场景可显式关闭。

12

TROUBLESHOOTING

卡住时，先定位哪一层坏了。

启动、模型、工作区、权限、上下文、MCP、子代理——多数故障都能先归到一层，再去看真实错误。

1启动2模型3工作区4权限5工具6上下文7扩展
01启动后没有自动打开页面

终端复制实际 URL；或主动使用 --no-open。默认是 127.0.0.1:3080。

023080 端口被占用

确认旧进程是否仍在运行，或使用 dsh web --port 8080。

03输入框一直不可用

先选择 Workspace；再检查模型路由是否可用、Provider 是否被删除。

04MISSING_CREDENTIAL / 401

在 Settings → Models 重新保存密钥。GET /models 不被端点支持时，手动录入模型。

05自定义网关每次请求都失败

常见是 developer role 或 max_completion_tokens 不兼容；查看官方 providers 文档的 compat 配置。

06图片发送前就被拒绝

手动添加的模型默认按纯文本；视觉模型要在 settings.yaml 声明 input: [text, image]。

07写入被拒绝

这通常说明沙箱正在工作。核对当前权限，只给一次性、最窄的必要升权。

08命令显示运行了，但任务仍失败

检查非零退出码与完整 stderr；不要把“工具被调用”当成“结果成功”。

09输出太长被截断

读取工具给出的 spill 文件，或缩小范围，不要盲目重复同一大请求。

10/compact 后仍超限

减少不需要的 MCP/工具，换新会话，只引用必要文件；单个巨大单元无法靠压缩变小。

11子 Agent 不理解背景

spawn 是新上下文：把目标、范围、证据、禁区、返回格式写成自包含委派。

12多个子 Agent 互相覆盖

共享工作区会产生竞争；拆开写入范围，或让子代理全部只读。

13MCP 启动了但工具没出现
